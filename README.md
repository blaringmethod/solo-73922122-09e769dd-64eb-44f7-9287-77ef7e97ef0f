# 网络安全分析台（规则差分 + 路由诊断）

两个面向网络变更安全审查的工具，共用同一个 FastAPI 服务与顶部导航：

1. **防火墙规则变更差分台**（`/`）：上线前比对两份**有序 IPv4/TCP 规则集**，
   精确列出规则变更会**新增放行**与**新增阻断**的全部流量区域。不做抽样：
   通过边界切分对整个流量空间做精确枚举。
2. **隔离网路由诊断**（`/route-diag`）：调整隔离网路由前，把**目标网段完整
   划分为互不重叠的地址闭区间**，给出每个区间内全部可能结果（经网关送达 /
   绕过网关送达 / 丢弃 / 无限循环），直接回答“受保护网段是否会绕过检查网关”。
   同样不做抽样：按前缀边界符号化切分，不逐 IP 枚举。

## 规则差分语义

* 仅支持 **IPv4 + TCP**；
* 每条规则：`id`（同一份规则集内唯一的整数或字符串）、`source`/`destination`
  （严格 IPv4 CIDR，主机位为 0；全网 `0.0.0.0/0`，单机 `a.b.c.d/32`）、
  `portRange`（目的端口闭区间 `[下界, 上界]`，0–65535 整数）、
  `action`（小写 `allow` / `deny`）；
* 按数组顺序匹配，**首条命中生效**；全部未命中即**默认拒绝**（DEFAULT DENY）；
* 每份规则集最多 **20 条**。

```json
[
  {
    "id": 1,
    "source": "10.0.0.0/8",
    "destination": "172.16.0.0/12",
    "portRange": [80, 443],
    "action": "allow"
  }
]
```

## 路由诊断语义

* 网络由 **≤ 8 台**路由器组成，每台一张路由表（**≤ 20 条，表内前缀唯一**）；
* 每条路由：`prefix`（严格 IPv4 CIDR）+ `nextHops`（**非空**下一跳列表，
  元素为路由器编号、`"deliver"`（送达）或 `"drop"`（丢弃））；
* 每跳按**最长前缀匹配**选择路由条目，**无匹配即丢弃**；
* 命中条目的多个下一跳，**每次转发可任选其一**（等价多路径，诊断取所有可能）；
* 报文从 `entryRouter` 进入；`gatewayRouter` 是判定“经网关 / 绕网关”的基准。

对目标 CIDR 中的每个目的 IP，全部可能行为归结为四种结果的集合：

| 结果 | 含义 |
| --- | --- |
| `delivered-via-gateway` | 存在一条**经过检查网关**并最终送达的转发路径 |
| `delivered-bypass` | 存在一条**不经过检查网关**并最终送达的转发路径 |
| `dropped` | 存在一条以丢弃告终的路径（显式 `drop` 或无匹配路由） |
| `loop` | 存在一条**无限循环**的路径（从入口可达的环） |

配置 JSON 示例（页面可一键载入“绕行示例”“循环示例”后再编辑）：

```json
{
  "entryRouter": 1,
  "gatewayRouter": 3,
  "targetCidr": "10.0.0.0/24",
  "routers": [
    {"id": 1, "routes": [
      {"prefix": "10.0.0.0/25", "nextHops": [3]},
      {"prefix": "10.0.0.128/25", "nextHops": [2, 3]}
    ]},
    {"id": 2, "routes": [
      {"prefix": "10.0.0.128/25", "nextHops": ["deliver"]}
    ]},
    {"id": 3, "routes": [
      {"prefix": "10.0.0.0/24", "nextHops": ["deliver"]}
    ]}
  ]
}
```

## 快速启动（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://127.0.0.1:8000           （规则差分）
# 浏览器打开 http://127.0.0.1:8000/route-diag （路由诊断）
```

端口默认只绑定宿主机回环地址（`docker-compose.yml` 中
`127.0.0.1:8000:8000`）。需要对局域网开放时改为 `"8000:8000"`。
容器内置健康检查，访问 `/api/health` 探活。

本地直接运行（无需 Docker）：

```bash
pip install -r requirements.txt
uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 页面与接口

两个页面共用顶部导航（规则差分 / 路由诊断）。

**规则差分（`/`）**

* `GET /`：单页界面，两个编辑框分别粘贴旧、新规则；
  * **分析变更**：调用差分接口并渲染结果；
  * **载入重叠规则示例**：一键载入内置的重叠 CIDR / 端口区间示例；
  * **清空输入与结果**。
* `GET /api/example`：返回可直接载入的示例 JSON；
* `POST /api/analyze`：请求体 `{"old": "<旧规则JSON文本>", "new": "<新规则JSON文本>"}`；
  * 成功：`{"ok": true, "result": {...}}`；
  * 输入无效：HTTP 400，`{"ok": false, "errors": [...]}`，每条错误标明
    所属规则集（`sheet`）、第几条规则（`ruleIndex`）、字段（`field`），
    JSON 语法错误另附行列号（`line`/`col`）。前端收到错误会**清除旧结果**。

**路由诊断（`/route-diag`）**

* `GET /route-diag`：路由诊断页，一个 JSON 编辑框承载完整配置；
  * **开始诊断**：调用诊断接口并渲染区间划分与见证路径；
  * **载入绕行示例 / 载入循环示例**：一键载入内置的可编辑示例；
  * **清空输入与结果**。
* `GET /api/route-diag/examples`：返回 `{"bypass": {...}, "loop": {...}}` 两份示例；
* `POST /api/route-diag/analyze`：请求体 `{"config": "<配置JSON文本>"}`；
  * 成功：`{"ok": true, "result": {...}}`；
  * 输入无效：HTTP 400，`{"ok": false, "errors": [...]}`，每条错误标明
    路由器（`routerId`）、第几条路由（`routeIndex`）、字段（`field`），
    JSON 语法错误另附行列号（`line`/`col`）。前端收到错误会**清除旧结果**。

## 输出如何读

### 规则差分

结果分「新增放行」「新增阻断」两组，每组由若干**互不重叠的三维长方体区域**组成：

* **源地址区间**、**目的地址区间**（闭区间；若恰好对齐一个 CIDR 会同时标注）、
  **目的端口区间**（闭区间）；
* **覆盖报文数** = 源地址数 × 目的地址数 × 端口数（以字符串返回，避免 32 位整数溢出）；
* **示例报文**：取三个区间的最小端点组成的具体 TCP 报文（源 IP → 目的 IP : 端口）。
  同一区域内任意报文的命中结果恒定，因此该报文即代表整块；
* **变更前 / 变更后判定**：分别给出命中规则的编号 `ruleId`、顺序 `ruleOrder`
  与动作；未命中任何规则时标记 `defaultDeny: true`、`ruleId: "DEFAULT-DENY"`。

### 路由诊断

顶部先给**结论横幅**（是否存在绕过检查网关的送达路径、是否存在无限循环），
随后是目标网段的**完整区间划分**：

* 每个区间是**互不重叠的地址闭区间**（若恰好对齐一个 CIDR 会同时标注），
  全部区间的并集恰好等于目标网段；同一区间内任意目的 IP 的可能结果集合
  **完全相同**；
* 每个区间列出该区间内**全部**可能结果（四种结果的子集），每种结果附：
  * **示例目的 IP**（落在该区间内）；
  * **一条真实可行的转发路径**：逐跳给出路由器、该跳命中的路由前缀与
    下一跳选择；检查网关节点高亮；送达 / 丢弃（区分“无匹配路由”与
    “路由指定 drop”）有终态标记；**无限循环路径用虚线框标出重复段**，
    并注明回到哪台路由器无限重复；
* 汇总条给出每种结果覆盖的区间数与地址数（地址数以字符串返回，避免溢出）。

## 精确性原理（无抽样）

### 规则差分

1. 收集两份规则集全部规则在三个维度上的边界（CIDR 的首尾地址、端口区间端点），
   把整个流量空间 `源 IPv4 × 目的 IPv4 × 端口 0..65535`
   切分为若干**基本单元**；在任一单元内部，每条规则对整个单元要么全命中、
   要么全不命中，故单元内每个报文的命中规则恒定。
2. 对每个基本单元分别按「顺序扫描、首条命中」计算旧、新命中规则
   （未命中记为默认拒绝）。
3. 把 `(旧命中, 新命中)` 完全相同且相邻的单元贪心合并为长方体区域；
   仅保留动作发生变化的区域，并按变化方向分成新增放行 / 新增阻断。
4. 输出区域两两互不重叠，且其并集恰好等于所有新旧判定不一致的流量，
   无遗漏、无重复。

### 路由诊断

1. 把所有路由前缀的边界（与目标 CIDR 求交后）作为切点，将目标网段切分为
   **基本区间**（至多 `2 × 8 × 20 + 1` 个）。在任一基本区间内部，每台路由器
   的最长前缀匹配结果恒定，因此**逐跳转发图恒定**、四种可能结果的集合恒定。
2. 在每个基本区间的转发图（≤ 8 个节点）上做可达性分析：
   经网关送达 ⟺ 入口可达网关且网关可达 deliver；绕过网关送达 ⟺ 在剔除网关的
   图上可达 deliver；丢弃 ⟺ 可达 drop 终态；无限循环 ⟺ 存在入口可达的环。
   每种成立的结果同时构造一条具体见证路径。
3. 把相邻且结果集合相同的基本区间贪心合并，得到目标网段的完整、互不重叠
   划分；见证路径取合并区间起点处的目的 IP（区间内行为一致，故对该区间
   任意 IP 的结果集合结论不变）。

实现见 `app/engine.py` 与 `app/route_engine.py`；`tests/` 中的穷举测试会在
受限子空间内**逐点 / 逐 IP 枚举**（非抽样）核对输出区域与区间的归属、
互不重叠性、无缝覆盖、报文/地址计数及见证路径的逐跳合法性。
