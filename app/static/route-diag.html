🛡 网络安全分析台 规则差分 路由诊断

隔离网路由诊断（最长前缀匹配 · 等价下一跳任选 · 全量可能结果）

编辑 JSON 路由表并指定入口路由器、检查网关与目标 IPv4 CIDR。系统按前缀边界把目标网段符号化切分为互不重叠的地址闭区间，给出每个区间内全部可能结果（经网关送达 / 绕过网关送达 / 丢弃 / 无限循环）及示例目的 IP 与转发路径，不逐 IP 枚举、不抽样。

路由配置 JSON（入口路由器 / 检查网关 / 目标网段 / 各路由器路由表）

配置格式：一个 JSON 对象，字段 entryRouter（入口路由器编号，报文由此进入）、 gatewayRouter（检查网关编号，判定“经网关 / 绕网关”的基准）、 targetCidr（目标 IPv4 CIDR，须为网络地址，如 10.0.0.0/24）、 routers（路由器数组，1–8 台）。每台路由器： id（整数，全网唯一）、routes（路由条目数组，≤ 20 条，表内 prefix 唯一）。每条路由： prefix（严格 IPv4 CIDR）、nextHops（非空数组，元素为路由器编号、"deliver"（送达）或 "drop"（丢弃））。 每跳按最长前缀匹配选条目，无匹配即丢弃；命中条目的多个下一跳每次转发任选其一，诊断给出所有可能结果。 
{
  "entryRouter": 1,
  "gatewayRouter": 3,
  "targetCidr": "10.0.0.0/24",
  "routers": [
    {"id": 1, "routes": [
      {"prefix": "10.0.0.0/25", "nextHops": [3]},
      {"prefix": "10.0.0.128/25", "nextHops": [2, 3]}
    ]},
    {"id": 2, "routes": [
      {"prefix": "10.0.0.128/25", "nextHops": ["deliver"]}
    ]},
    {"id": 3, "routes": [
      {"prefix": "10.0.0.0/24", "nextHops": ["deliver"]}
    ]}
  ]
}
